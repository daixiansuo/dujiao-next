# Design

## Context

详见 proposal.md。整合基线为 id-1.1.1 的 3f22b3bf 与 main 的 f7b4354f；初始推演 39 个冲突文件，另有 33 个双方修改的自动合并文件。

## Goals / Non-Goals

**Goals:** 沿 main 新组件和调用链迁移定制；两个定价模式在所有入口一致；三模板验收一致。

**Non-Goals:** 不新增分类固定额、个人优惠价排序或额外插件框架，不自行提交或部署。

## Decisions

- 完整合并后逐块解决而非整文件选旧版，逐项核对 54 个上游 fix 最终行为。
- 固定金额独立于分类比例；百分比复用 main 分类继承和安全跳过。保留字段级更新、成本和 SKU 映射等共用修复。
- 删除分段专属计算和接口；旧数据库列不主动删除，未知模式禁止回退并允许显式纠正。生产数据只读清点，转换参数待逐连接确认，不执行生产迁移。
- 前台复用 CategoryTree、分类工具和 ProductCardStage，迁入官方目录/详情/公共取价；为 atelier 补同等功能而保留视觉。
- 保留备份、图片、排序、去广告和发布约定；Bot 先做契约核验，有差异才最小修改。

## Risks / Trade-offs

- 自动合并不等于行为正确 → 审查共享入口与新增组件，保留上游及定制测试。
- 旧 segmented 记录无法统一等价转换 → 不自动转换，清点后逐连接选择并告知下次同步改价影响。
- 外部环境可能不可用 → 本地测试与真实 PostgreSQL、Telegram、支付验收分开记录，不提前声称通过。

## Migration Plan

不写生产配置或数据库；交付代码与明确的迁移前置条件。既有列保留，运行时保护未转换配置；上线前先确认连接清单及目标参数，回退使用合并前版本和部署前备份。
