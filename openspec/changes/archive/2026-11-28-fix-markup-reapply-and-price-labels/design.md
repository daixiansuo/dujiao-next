# Design

## Context

见 proposal.md。定时同步已有分页设置，公共扫描却使用独立常量；SKU 的整行 Save 和错误丢弃使重算结果不可靠。项目已有商品映射事务装配，SQLite 仅单写连接，事务内不得使用全局仓储或请求上游。

## Goals / Non-Goals

**Goals:** 复用分页配置和现有事务，控制到字段的写入，并准确反馈保存与重算两个阶段。

**Non-Goals:** 不新增任务系统、数据库字段、依赖或计价算法；不操作生产及历史数据。

## Decisions

- 公共扫描显式传入现有分页配置，未装配设置时采用已有默认值；保留分页上限及响应分页回声处理。
- 每件商品复用可用性事务的绑定仓储，先锁映射再读写规格，保持与同步、停售一致的锁顺序；新增仅写售价和成本的窄方法，不复用整行 Save。
- 同一商品写失败回滚，其他商品继续并汇总失败，成功数量仅统计完整提交的商品。
- 外部分类查询在事务外完成。连接保存失败与自动重算失败分别反馈；自动重算请求由页面统一提示，其他请求维持全局鉴权处理。
- 将优惠价签移到价格下方，售罄标识仍在状态区域；保持原取价优先级和按钮布局。

## Risks / Trade-offs

- 部分商品成功、部分失败 → 日志及返回结果明确失败，重试按当前上游成本重新计算，不累计加价。
- 分类树不可用 → 保留现有跳过改价保护，返回明确提示，不按默认价替代。
- 并发和单连接事务 → 统一映射优先锁序、全部使用事务绑定仓储，以真实 SQLite 回滚测试验证。

## Migration Plan

无需数据迁移。本地测试及构建完成后交付，部署、提交和推送另行按用户指令处理。
